# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Research project on the **adaptive relational bottleneck**. The core mechanism is *adaptive relational cross attention* (ARCA), which uses a scalar γ to interpolate the attention values between the context itself (cross attention) and abstract identity symbols (relational cross attention / the relational bottleneck):

$$\text{ARCA}(X_q, X_c) = \text{softmax}\left(\frac{(X_qW_q)(X_cW_k)^\top}{\sqrt{d}}\right)\left[(1-\gamma)X_c+\gamma I\right]W_v$$

- γ=0 → cross attention
- γ=1 → relational cross attention (relational bottleneck)

γ is either fixed, learned online by backprop, meta-optimized through an unrolled inner loop, or set by a Lagrangian/closed-form rule. Each strategy has its own experiment folder (see below). See `README.md` for results and current project status.

## Layout

### `src/adaptive_bottleneck/` (the installable package)

- **models.py**: γ-interpolated attention.
  - `init_gamma_value_attn_params(key, in_dim, attn_dim, val_dim)` returns `{"W_q", "W_k", "W_v"}`.
  - `gamma_value_cross_attention_forward(params, X_context, X_query, gamma, linear=False)` is ARCA. Most experiments use it.
  - `gamma_value_self_attention_forward(params, X, gamma, linear=False)` is the self-attention variant (block task).
  - `init_classifier_params`, `forward_logits` and `forward_multinomial_logits` are linear readout heads over self-attention output.
- **tasks.py**: synthetic tasks (jax_dataloader wrappers).
  - `XOR`.
  - `BlockComparison`: are all one-hot vectors in the same half?
  - `ContextIdentification`: which context item is closest to the query?
    - `label_mode`: `"feature"`, `"position"` or `"both"`.
    - `input_mode`: `"self"` or `"cross"`.
    - `positional_codes`: one-hot position codes appended to context rows.
    - `generate_all_examples()` enumerates the full population, returning numpy arrays.
  - `train_test_split_indices()` gives nested, condition-independent splits.
- **save.py**: `save_results_json`, `_save_params_pkl` (call `jax.device_get` before pickling) and `_ensure_dir`.
- **analysis.py**: attention-weight visualization. **utils.py**: `load_plot_config` and small helpers.

### `scripts/`

- `block_task/`: block-comparison γ sweep, plus meta/online γ. The meta/online scripts import helpers from the sibling `block_adaptive_bottleneck.py`.
- `xor/`: XOR comparisons of `rca` / `cross_attn` / `arca`.
- `context_identification/`, split by γ strategy:
  - `fixed_gamma/`: fixed-γ sweep.
  - `online_gamma/`: γ learned by backprop.
  - `meta_gamma/`: γ meta-optimized.
  - `lagrange_gamma/`: Lagrangian / regression γ.
  - `pos_codes/`: ARCA vs positional-code baselines. This covers the original comparison, full-batch, weight-scale and sampling-percentage sweeps.
  - Analysis of a fixed-γ model belongs in `fixed_gamma/`. `learnable_gamma_*` outputs belong in `online_gamma/`.
- `tests/`: standalone check scripts. Some `sys.path.insert` into `pos_codes/` to reuse sweep code.
- `della/`: a generic SLURM array template for the CCN sweeps.

`results/` mirrors the `scripts/` layout (figures and small CSVs, tracked). `docs/` holds the LaTeX write-ups (derivations, task descriptions, figures).

### `slurm/`

SLURM jobs for the large pos_codes sweeps. The convention is **profile, then size**. A `*_profile.sh` script runs one worst-case task with generous limits. Its measured wall clock and peak RSS then set `--time` and `--mem` in the matching `*_sweep.sh`, with the measurements recorded in comments. Jobs `cd` to the repo root and write logs to `slurm/logs/` (gitignored).

### `claude/`

Dated session logs (`claude/YYYY_MM_DD/`, with `TODO.md` and `SUMMARY.md`/`SESSION_NOTES.md`). They record the reasoning behind past experiments. Read the most recent few for context before starting new work. Early logs (January 2026) mention a dual feature/position decoder and signed interpolation. That side project has since been removed from the code.

## Conventions

- **Paths are relative to the repo root.** Scripts read and write `./data/...` and `./results/...`. Notebooks in `notebooks/<topic>/` use `../../data/...`.
- **`data/` is gitignored.** It holds raw sweep JSONs and model pickles, which are regenerated by the scripts. Don't assume a given data file exists locally.
- **Naming**: `_sweep` is for scripts that vary a parameter over a range. `_comparison` is for scripts that run a fixed set of named conditions side by side (e.g. `adaptive` / `adaptive_pos` / `attn_pos`).
- **JAX-first**: use explicit `jax.random` keys, Optax (AdamW for model params, usually SGD for γ), `jax.jit` train steps, and γ clipped to [0, 1].
- **Faithful implementations**: when a derivation exists in `docs/`, implement its formulas exactly rather than approximating.
